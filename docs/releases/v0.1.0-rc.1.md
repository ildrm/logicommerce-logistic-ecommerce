# LogiCommerce v0.1.0-rc.1 release notes

Release date: pending production approval  
Release type: production release candidate

## Highlights

- Added a fail-closed production release workflow with immutable commit-SHA
  images, image vulnerability scans, forward migrations, stable-service waits,
  and a final readiness probe.
- Added an AWS ECS/Fargate production reference stack with Multi-AZ MySQL,
  encrypted Valkey and S3, private application networking, ALB/WAF ingress,
  autoscaling, centralized logs, alarms, KMS encryption, and protected stateful
  resources.
- Added explicit, machine-validated release evidence gates. Deployment cannot
  begin while provider certification, penetration/privacy reviews, restore
  drills, telemetry/on-call, staging acceptance, or migration review is stale
  or absent.
- Added an independently enforced domain-critical coverage gate for abuse
  throttling, authorization, and document scanning. The measured local result
  is above 80% for statements, branches, functions, and lines.
- Added CI scans for the built API, worker, web, and migration images in addition
  to source scanning and SBOM generation.

## Security and reliability

- Password-reset, passwordless-login, and verification-email requests now use a
  privacy-preserving Redis-backed recovery limiter that fails closed when the
  shared limiter is unavailable.
- The web application now emits a restrictive Content Security Policy alongside
  the existing security headers.
- High-risk user and freight-request collections are bounded to 100 records to
  prevent unbounded control-plane responses.
- Scanner tests now cover deterministic network-free behavior and fail-closed
  handling of incomplete HTTP-provider configuration.
- Final runtime images remove npm, Corepack, and their unused package-management
  dependency trees. The Node.js 24.19.0 undici WebSocket finding has a scoped,
  documented acceptance that expires on 2026-09-03; no WebSocket path is
  exposed, and the next patched Node.js 24 release must replace it.

## Deployment notes

- Production images require Node.js 24 and pnpm 11.15.1.
- Configure the protected GitHub `production` environment and the AWS/OpenTofu
  variables documented in `infrastructure/aws/production/README.md`.
- Bootstrap the remote state and account-owned infrastructure prerequisites,
  populate the application secret through the approved secret workflow, and
  validate an OpenTofu plan before the first deployment.
- Use a full green commit SHA when invoking the release workflow. Mutable image
  tags are not accepted.

## Known release gates

This candidate is not authorized for production until every pending entry in
`release/evidence.json` is replaced with genuine, current evidence. The whole
API coverage baseline is 10.81% lines; the new 80% gate is deliberately
limited to the named release-critical controls and must not be represented as
80% coverage of the complete API.
